# VisionPLC：纸面手写实时视觉编程系统——步骤级实施手册

> 版本：V2.0（最终方向冻结版）
> 日期：2026-10-15
> 平台：安路 PH1P35 / HX1P35A
> 架构：FPGA视觉识别 + 片内RISC-V MCU编译调度 + FPGA硬实时执行接口
> 输入：普通白纸上最多8个手写数字
> 展示：可插拔执行器；比赛推荐成品桌面机械臂，但不是系统必需品

---

## 0. 项目最终定义

### 0.1 一句话定义

> 用户在普通白纸上写一串数字，FPGA实时识别并恢复阅读顺序，片内MCU把数字序列编译成经过安全检查的控制程序，再由FPGA确定性地控制外部设备执行。

数字是**程序指令**，不是被分类、搬运或分拣的物体。

### 0.2 核心创新

1. **纸就是程序载体**：不依赖电脑键盘、触摸屏、二维码或专用程序板。
2. **视觉即编程入口**：识别类别、位置和置信度，并自动恢复程序顺序。
3. **异构实时架构**：FPGA负责视频与确定性I/O，片内MCU负责语义、编译和任务调度。
4. **全过程可解释**：显示源程序、编译结果、程序计数器、当前动作和错误原因。
5. **执行器可插拔**：同一语言可控制机械臂、舵机、灯、蜂鸣器、继电器或教学装置。
6. **不确定就拒绝**：看不清、布局歧义、程序非法时绝不猜测执行。

### 0.3 V1必须实现

- A4/A5普通白纸，黑色粗头笔书写1～8个数字。
- 支持单行或两行、大小和间距有合理变化的非粘连数字。
- 按“从上到下、每行从左到右”恢复程序顺序。
- 连续3帧一致后冻结不可撕裂的视觉快照。
- MCU完成静态检查、编译、动作展开和运行调度。
- FPGA提供APB、中断、心跳看门狗和至少一种硬实时输出。
- 小屏显示状态，主画面显示框、序号、源程序和执行高亮。
- 支持RUN、PAUSE、RESET和急停/安全输入。
- 用单舵机或机械臂完成端到端演示。

### 0.4 V1不做

- 不承诺任意潦草、连笔、遮挡、重叠或三行以上的书写。
- 不在RUN状态按每一帧图像热修改正在执行的动作。
- 不实现完整IEC 61131-3、G代码或通用机器人逆运动学。
- 不依赖切割、钻孔、洞洞板、定制PCB或3D打印。
- 不把3018、传送带或任何特定机械结构设为必购件。
- 不由FPGA开发板给舵机、电机或大功率负载供电。

### 0.5 当前进度

| 阶段 | 状态 | 已有证据 | 下一验收门 |
|---|---|---|---|
| S0 视频与多目标识别 | 基本具备 | 视频、摄像头、小屏/显示链路可运行 | 归档8目标和30分钟稳定性记录 |

## 1. 最终演示与系统结构

### 1.1 标准演示

1. 上电后视频、MCU和执行器处于SAFE。
2. 用户在普通白纸写：`1 2 5 3 6 8 0`。
3. 画面为每个数字标出类别和阅读序号。
4. 连续3帧稳定，小屏显示`SRC LOCKED`。
5. MCU显示编译结果：

   ```text
   HOME -> A -> PICK -> B -> DROP -> VERIFY -> END
   COMPILE PASS
   ```

6. 用户按RUN，设备按程序执行；视频同步高亮当前数字。
7. STOP状态换一张纸，系统重新识别和编译另一程序。
8. 演示非法程序、运行中换纸、MCU心跳丢失和急停，系统拒绝或安全停止。

### 1.2 系统框图

```text
普通白纸手写数字
        │
摄像头 → FPGA视频流水线 → 多目标识别 → 阅读顺序/稳定判定
                                           │ 原子快照
                                           ▼
                                  APB寄存器 + CLIC
                                           │
                                           ▼
                                    片内RISC-V MCU
                              静态检查 → 编译 → 调度
                                           │ 动作队列
                                           ▼
                                  FPGA可插拔执行器后端
                                  PWM / I²C / UART / GPIO
                                    │        │       │
                                  机械臂   单舵机   灯/继电器
```

### 1.3 执行器为什么不是必需品

VisionPLC的核心验收对象是“纸面程序能否可靠读取、编译并安全执行”。外设只是让执行结果可见。S0～S9可以用LED、蜂鸣器或单舵机完成，比赛时再接成品机械臂。因此不会因为机械采购延期阻塞软件主线，也不会让项目变成机械加工题。

## 2. 普通白纸程序规范

### 2.1 支持范围

| 项目 | V1规格 |
|---|---|
| 纸张 | 白色A4或A5，无明显格线和强反光 |
| 笔 | 黑色粗头马克笔，推荐线宽2～5 mm |
| 数量 | 1～8个数字 |
| 排版 | 单行或两行，允许轻微倾斜 |
| 单字高度 | 建议25～60 mm |
| 字间距 | 建议≥10 mm，外接框不得明显重叠 |
| 光照 | 无频闪、无强阴影、纸面不过曝 |
| 拒绝 | 连笔、接触、涂改覆盖、严重折痕、超过两行 |

可选八格打印纸只用于训练和调试。最终演示必须能使用没有格子的普通白纸。

### 2.2 阅读顺序算法

1. 筛除低置信度目标，最多保留8个。
2. 计算检测框高度中位数`Hmed`。
3. 按中心Y初排；中心Y差不大于`0.5 × Hmed`的框归为同一行。
4. 行按平均Y从小到大排序，行内按中心X从小到大排序。
5. 依次赋予`token_index=0..N-1`。
6. 行归属处于临界区、框重叠或顺序跨帧跳变时置`LAYOUT_AMBIGUOUS`并禁止编译。

### 2.3 稳定提交

只有以下条件全部满足才产生`VISION_COMMIT`：

- 连续3帧数量一致；
- 数字序列完全一致；
- 对应框中心漂移≤8像素；
- 所有置信度高于编译阈值；
- 无重叠、越界和布局歧义；
- 快照写完后再递增`VIS_SEQ`并触发中断。

快照至少包含：

```text
seq, token_count, token[8], confidence[8], bbox[8],
layout_flags, source_crc, timestamp
```

MCU读序号、读整批数据、再读序号；两次不同则整批重读。

### 2.4 运行时换纸

- STOP：重新稳定和编译，替换待运行程序。
- PAUSE：允许重新编译，但必须重新按RUN确认。
- RUN：置`SOURCE_CHANGED`，禁止混用新旧程序；完成当前不可分割小动作后安全暂停，严重故障立即停机。

## 3. 数字指令语言 VPL-10

### 3.1 操作码

| 数字 | 指令 | 机械臂语义 | 通用I/O语义 |
|---:|---|---|---|
| 0 | `END` | 结束并进入安全保持 | 输出回安全态 |
| 1 | `HOME` | 回到安全初始姿态 | 初始化输出 |
| 2 | `MOVE_A` | 移动到姿态A | 场景/输出A |
| 3 | `MOVE_B` | 移动到姿态B | 场景/输出B |
| 4 | `MOVE_C` | 移动到姿态C | 场景/输出C |
| 5 | `PICK` | 下降、夹取、抬起 | 执行器1置位 |
| 6 | `DROP` | 下降、释放、抬起 | 执行器1复位 |
| 7 | `WAIT` | 等待500 ms | 等待500 ms |
| 8 | `VERIFY` | 请求视觉/传感器确认 | 检查输入条件 |
| 9 | `PAUSE` | 安全暂停等待确认 | 暂停程序 |

操作码与设备后端分离，编译器先输出统一IR，再由机械臂或I/O后端展开。

### 3.2 示例

```text
1 2 5 3 6 8 0
HOME → A → PICK → B → DROP → VERIFY → END
```

```text
1 4 7 2 9 0
HOME → C → WAIT → A → PAUSE → END
```

### 3.3 静态检查

1. 长度1～8。
2. 恰好一个`END`，其后无指令。
3. V1要求第一条是`HOME`。
4. `HOME`前不允许动作。
5. `DROP`前必须存在未配对`PICK`。
6. 结束时工具状态必须安全。
7. 展开后IR不超过64条。
8. 估算总运行时间不超过30秒。
9. 姿态已标定且关节角在软限位内。
10. 源CRC、编译器版本、执行器配置匹配。

### 3.4 编译管线

```text
Token流 → 快照检查 → 语法检查 → 设备无关IR
       → 安全/资源检查 → 后端展开 → 时间估算 → PROGRAM_READY
```

`PICK`可展开为：

```text
POSE(PICK_ABOVE) → POSE(PICK_DOWN) → GRIP(CLOSE)
→ WAIT(300ms) → POSE(PICK_ABOVE)
```

### 3.5 错误码

| 代码 | 含义 | 处理 |
|---|---|---|
| `E01 LOW_CONF` | 置信度不足 | 重写或改善光照 |
| `E02 LAYOUT` | 顺序歧义 | 拉开间距 |
| `E03 NO_END` | 缺少0 | 末尾补0 |
| `E04 AFTER_END` | 0后仍有指令 | 删除后续数字 |
| `E05 NO_HOME` | 首指令不是1 | 开头补1 |
| `E06 DROP_FIRST` | 先释放后夹取 | 调整5、6顺序 |
| `E07 UNSAFE_END` | 结束状态不安全 | 补充释放动作 |
| `E08 TIME_LIMIT` | 运行时间超限 | 缩短程序 |
| `E09 SOURCE_CHANGED` | 运行中纸面变化 | 停稳后重确认 |
| `E10 ACTUATOR` | 执行器故障/超时 | 排查供电和连线 |

## 5. 连接、供电与安全

### 5.1 电源树

```text
开发板原装电源 ─────────────→ FPGA/摄像头/小屏

执行器专用适配器 → 急停常闭触点 → 保险/分配板 → 舵机/机械臂
                                      │
FPGA GND ─────────────────────────────┴→ 逻辑公共地
```

禁止从开发板5V/3.3V给机械臂供电。急停必须物理切断执行器电源，而不是只发一个软件信号。

### 5.2 逻辑信号

实际FPGA管脚必须依据当前原理图和约束分配，本手册不虚构针脚号。

| 信号 | 方向 | 电平 | 说明 |
|---|---|---|---|
| `btn_run_n` | 输入 | 3.3V | RUN，需消抖 |
| `btn_pause_n` | 输入 | 3.3V | PAUSE，需消抖 |
| `btn_reset_n` | 输入 | 3.3V | 清错/复位 |
| `estop_fb_n` | 输入 | 3.3V | 急停辅助触点 |
| `act_safe_en` | 输出 | 3.3V | 外部输出总使能 |
| `i2c_scl/sda` | 双向 | 3.3V | PCA9685路线 |
| `arm_uart_tx/rx` | 双向 | 经电平转换 | xArm路线 |
| `status_r/y/g` | 输出 | 3.3V | 状态灯 |

### 5.3 上电步骤

1. 执行器断开，只上开发板电源。
2. 万用表确认没有5V误入3.3V信号。
3. 烧录FPGA和MCU，确认视频、UART、S2/S3自检。
4. 用原厂控制器独立完成执行器到货测试。
5. 全部断电后连接公共地和控制线。
6. 先用逻辑分析仪确认波形，再接舵机控制端。
7. 首次动作限制为小角度、低速，人员离开运动范围。
8. 验证急停物理断电和FPGA状态反馈。
9. 最后接完整机械臂。

验收：急停后执行器电源在100 ms内断开；复位不会自动恢复运动；必须重新HOME、编译并按RUN。

## 6. 软件分层与接口

### 6.1 FPGA模块

```text
video/: digit_detector, bbox_postprocess, reading_order,
        source_stability, vision_snapshot_cdc, overlay_renderer
mcu/:   RISC-V IP, AHB-to-APB mailbox, APB regs,
        irq_controller, heartbeat_watchdog, safe_output_gate
act/:   action_fifo, pose_interpolator, pwm/i2c/uart backend,
        limit_checker, timeout_monitor
```

### 6.2 MCU模块

```text
app/: main, event_loop, vision_source, vpl_parser,
      vpl_compiler, safety_manager, runtime, ui_model
hal/: fpga_apb_hal, irq_hal, button_hal, log_hal
```

ISR只置事件标志并暂时屏蔽对应源；APB访问、W1C、编译和日志放在主循环，避免邮箱重入。

### 6.3 当前已验证接口

- MCU访问FPGA邮箱的CPU侧AHB窗口：`0x80000100`。
- APB `IP_ID = 0x56504C43`。
- 当前APB版本：`0x00020000`。
- 当前S3寄存器范围：`0x000～0x030`。
- 当前CLIC中断号：SDK编号27，已由板上`S3 CLIC IRQ 5/5 PASS`验证。

### 6.4 规划寄存器分区

| APB偏移 | 分区 | 内容 |
|---|---|---|
| `0x000～0x0FF` | SYSTEM | ID、版本、中断、心跳、安全、故障 |
| `0x100～0x1FF` | VISION | Token、框、置信度、序号、CRC |
| `0x200～0x2FF` | PROGRAM | 编译状态、错误、PC、IR队列 |
| `0x300～0x3FF` | ACTUATOR | 姿态、通道、目标、完成、超时 |
| `0x400～0x4FF` | UI/VERIFY | 屏幕邮箱、验证结果、调试计数 |

这是规划表，不得宣称已经实现。多位数据跨时钟域必须使用握手或异步FIFO。

### 6.5 双仓库职责

| 仓库 | 内容 |
|---|---|
| FPGA主仓库 | 视频、识别、MCU实例、APB、CDC、中断、安全门、执行器RTL |
| `VisionPLC_MCU_Firmware` | BSP、链接脚本、应用、编译器、运行时、板测文档 |

## 7. S0～S13步骤级实施

### S0：视频基线

**目标**：冻结增加MCU功能前的视频基准。

步骤：保存可工作提交/bit/约束；运行30分钟；测试1、4、8目标；归档视频和帧率。

验收：30分钟无死屏，8目标输出稳定，可一键回退到基线。

下一步：基线可复现才继续；当前可补做证据归档。

### S1：MCU工具链

**状态：已通过。** ELF可编译、OpenOCD/GDB可下载、可进入`main()`、UART可输出。BSP/HPF变更后重新回归Hello World。

### S2：APB闭环

**状态：已通过。** 必须长期保留以下回归：

```text
APB IP_ID: 0x56504C43 PASS
APB byte strobes PASS
APB PSLVERR read/write PASS, legal access recovered
APB SCRATCH 10000/10000, errors=0 PASS
APB IRQ source 100/100 PASS
STAGE_B PASS
```

APB RTL修改后必须全量回归，不能只读ID。

### S3：CLIC、中断、心跳和安全门

**状态：已于2026-10-15通过板上验收。** 实测看门狗超时197 ms；屏幕背光已与安全输出解耦。

步骤：烧录当前S3；确认5类IRQ；MCU每50 ms心跳；用GDB暂停MCU；确认200 ms撤销安全输出；按`CLEAR → HEARTBEAT → ARM`恢复；冷启动/复位/急停各10次。

验收日志：

```text
S3 CLIC IRQ 5/5 PASS, CLIC_ID=27
S3 heartbeat 50ms keepalive PASS
S3 MCU_TIMEOUT 200ms PASS, safe output OFF
S3 explicit CLEAR + HEARTBEAT + ARM recovery PASS
STAGE_S3 PASS
VISIONPLC MCU READY
```

回归准则：APB、安全RTL、MCU中断或时钟复位发生修改后，必须重跑本阶段全部日志。

### S4：白纸手写数字与阅读顺序

步骤：采集至少10人、每人每类20个样本；按书写者划分训练/验证/板测集；实现两行聚类；实现低置信度、重叠、第三行、超过8个的拒绝；叠加阅读序号；测试20张无格白纸。

验收：合法序列准确率≥98%；非法布局拒绝率≥95%；同一纸面连续100帧顺序不跳。

下一步：必须同时证明“能读对”和“看不清会拒绝”。

### S5：原子视觉快照

步骤：实现`VIS_SEQ`、数量、8组Token/框/置信度和CRC；视觉域写影子寄存器再一次提交；APB域更新可见快照并中断；MCU双读序号；仿真随机在写入中读取。

验收：仿真10万次无撕裂；板上更新1万次CRC/序号错误为0。

下一步：出错必须丢弃整批，不能使用半批数据。

### S6：VPL-10编译器

步骤：编写不访问硬件的纯C解析器；实现全部静态规则；生成≤64条IR和运行时间估算；建立正反用例；固定编译CRC和版本。

验收：至少50个合法、50个非法用例全部通过；PC与MCU编译结果逐字节一致；同输入重复编译确定一致。

下一步：编译器完全不依赖摄像头和机械臂。

### S7：无电机运行时

步骤：实现`SAFE/STOP/READY/RUN/PAUSE/FAULT`；定时器模拟动作完成；逐条打印PC/opcode/start/done；测试按钮、换纸、超时；画面高亮当前Token。

验收：1000个随机合法程序无死锁；故障最终进入SAFE/FAULT；RESET不自动RUN。

下一步：状态机通过才连接SG90。

### S8：执行器RTL仿真

步骤：实现动作FIFO、命令ID/完成ID、超时、取消、软限位和安全门；选择I²C/PWM/UART一个后端；覆盖正常、边界、超时、急停、心跳丢失；执行CDC检查。

验收：自检仿真全PASS；非法目标不产生输出；撤销安全门立即进入定义的安全态。

下一步：先看波形再接负载。

### S9：电气台架

步骤：空载测I²C/PWM/UART；检查电平、频率、占空比/帧；接LED和一个SG90，动作限制±15°；用两张纸运行不同程序；注入急停和心跳超时。

验收：100次顺序零错误；急停和超时均关断；FPGA不异常复位。

下一步：S9通过后才有必要购买或接机械臂。

### S10：机械臂独立验收

步骤：验货；用原厂控制器完成HOME和小范围动作；记录通道、零位、方向和安全角；测动作压降；验证急停物理断电。

验收：原厂路径20次无卡死；无异常发热；供电在允许范围。

下一步：失败先退换货，不改FPGA软件掩盖机械问题。

### S11：姿态标定与后端

步骤：固定机械臂；标定`HOME/A/B/C/PICK_ABOVE/PICK_DOWN`；记录关节软限位和最大速度；分段插值；动作超时；保存校准版本和CRC。

验收：每姿态往返50次无碰撞；重启后HOME可复现；配置错误禁止ARM。

下一步：单动作稳定后才运行整张纸。

### S12：端到端闭环

步骤：准备10个合法、10个非法程序；逐一核对Token、IR、动作；STOP状态换纸；RUN状态移动/遮挡纸；重复标准演示100次并记录失败类别。

验收：识别+编译正确率≥98%；动作顺序100%；非法程序不得驱动；100次端到端成功率≥95%。

下一步：所有失败必须能归因，不能保留“偶现未知”。

### S13：比赛化和证据包

步骤：固化匹配标签、bit、ELF；准备纸、笔、备用线和最小执行器；录制正常、换程序、非法程序、急停、心跳丢失；做遮挡、断串口、执行器掉电等故障注入；完成3分钟讲解；陌生队员操作10轮。

验收：10轮无需改代码；任一故障2分钟内可定位；安全故障均无失控动作。

## 8. 测试矩阵

| 测试 | 注入 | 期望 |
|---|---|---|
| 低置信度 | 模糊/浅色数字 | 不提交程序 |
| 数字粘连 | 两数字相接 | `E02 LAYOUT` |
| 缺少END | 不写0 | `E03 NO_END` |
| RUN时换纸 | 替换纸面 | 当前原子动作后安全暂停 |

| MCU停止心跳 | GDB暂停 | 200 ms撤销安全门 |
| 动作超时 | 屏蔽DONE | FAULT并停止后续动作 |
| 急停 | 按下按钮 | 物理断电且记录状态 |
| 配置不匹配 | 改CRC/版本 | 禁止ARM |
| 执行器掉电 | 断其电源 | 超时FAULT，不自动重启 |

## 11. 每日安全操作

开机：检查运动范围 → 急停按下 → 上开发板 → 确认S2/S3与SAFE → 释放急停 → 上执行器 → HOME → 放纸 → 编译 → RUN。

关机：PAUSE/STOP → HOME → 按急停 → 先断执行器 → 再断开发板 → 保存日志。

红线：不带电插拔舵机；不使用裸露市电端子；不绕过急停、软限位或心跳；不让不确定的识别结果执行；不在RUN时用GDB改关键变量后继续动作。

| 类别 | 指标 |
|---|---|
| 视觉 | 普通白纸合法序列准确率≥98% |

| 总线 | S2全部回归PASS |
| 安全 | 心跳丢失200 ms内撤销输出 |

| 端到端 | 标准演示100次成功率≥95% |
| 可复现 | 冷启动无需改代码可演示10轮 |

答辩核心话术：

> 这不是识别数字后做固定动作，而是把现实中的手写符号编译成可验证、可追踪、可安全执行的控制程序。FPGA负责看得快、执行准，片内MCU负责读懂程序和处理控制语义；机械臂只是一个可更换的执行插件。
